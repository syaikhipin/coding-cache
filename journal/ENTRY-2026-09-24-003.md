# Entry 003 — 2026-09-24 — Review-driven rebuild: prefix-stability metrics, volume-equalized archetypes, robustness sweep

## Provenance

Entry 002's conclusions rested on a harness with three implementation defects
found by an external adversarial review (Round 1, score 3/10; full review in
`../review-stage/AUTO_REVIEW.md`):

1. `frozen_tools` was assigned **after** the request loop consumed it —
   D5 "frozen" never actually froze anything.
2. The OpenAI cache model lacked 128-token block quantisation and pruned
   entries after reading; the Anthropic model pruned after reading, allowed
   unbounded breakpoints, and wrote sub-1024-token entries.
3. PFS's cache-aware compaction request received the **mutated** env, so the
   "frozen" compact prefix was never frozen (read 0 tokens instead of ~17k).

Additionally, compaction fired at step 1 (threshold 1500 tokens) because the
fixture's stable prompt regions were toy-scale, and archetype system prompts
carried unequal stable volume (~3.9k tokens in PFS vs ~130 in RC) — a
volume confound, since sub-1024-token stable fronts are not even cacheable
under either provider's documented minimum.

## What was rebuilt

- Simulator (`minicache/simulator.py`): prune-before-read, ≤4 breakpoints
  enforced, 1024-token minimum entry floor, 128-token block quantisation
  (OpenAI), `turn_only` + absolute billed-token + no-cache-baseline splits
  in every summary.
- Metrics (`minicache/metrics.py`): cache_control-stripped canonical
  serialisation; **transcript resets reported separately from early-prefix
  invalidations** (message-list elementwise-prefix check per pair).
- Harness (`minicache/harness.py`): D3 frozen = append-only env-note
  delivery; **uniform post-compaction retention** across all D4 policies
  (D4 varies only how the summary request is constructed); compact request
  receives the frozen env for frozen archetypes.
- Prompts (`minicache/prompts.py`): stable instruction volume equalised
  across archetypes (~3.9k tokens each) so stability is not confounded with
  prompt volume; README fixture padded to ~12k tokens; compaction threshold
  retuned to 12400 (fires at step 7 for every archetype).
- New driver `experiments/sweep.py` (E4): 4 churn schedules × 3 session
  lengths × 3 compaction thresholds × 3 archetypes + 3 alternate-task cells
  = 111 runs over 37 conditions.

## Conclusions that changed

- **Stratification is pure relocation** (C4 = exactly 0.0pp now that
  content and ordering are held fixed; A3 = +8.8pp). Entry 002's
  "near-neutral D1" was an artifact of the volume confound: with equal
  stable volume, the only thing that matters is where mutable content sits.
- **D4 and D6 act on the measurement composition, not turn-level
  stability**: turn-only deltas are 0.0pp in this schedule; their
  all-request deltas come from the summary request's own readability and
  warmer self-hits. Warmer **strictly increases** absolute billed tokens.
- **The ranking PFS > MC > RC survives 37/37 sweep conditions** under both
  cache models; the margin compresses to 1.5pp with no churn and no
  compaction and reaches 24.1pp with churn + mid-session compaction.
